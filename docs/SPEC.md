# M4·M5 요구사항 명세서

작성일 2026-10-19 · 담당 M4·M5 (팀원 2명) · 팀 기준 개정 2026-10-29 (4절 끝 「팀 기준 개정」)

## 1. 개요

유속계 정도검사 04단계(시험데이터 정리)와 05단계(CLAYDOX 입력 준비)를 자동화한다. 시험자가 풍동 프로그램이 만든 rawdata CSV 6개를 넣으면, 도구가 반복성·직선성·설치방향 민감도를 계산·판정하고 CLAYDOX가 읽을 Excel 하나를 만든다.

- 형태: HTML 파일 하나 (가정: 사용자 최종 확인 대기. exe 하나로 낼지는 사용자 결정 대기, FR-F-07). 실험 PC에서 더블클릭으로 연다.
- 서버·설치·인터넷 연결 없음. 데이터는 저장하지 않는다.
- 결과 Excel은 KTL이 쓰던 `계산식.xlsx`와 같은 모양이다. 시험 담당자는 이 파일을 CLAYDOX의 RAW DATA 첨부 칸에 넣는다.

## 2. 사용 흐름

팀 기준 개정(2026-10-29)으로 흐름이 4단계가 되었다 (근거 팀03 A-7). 단계 사이는 「다음」과 「뒤로」 버튼으로만 이동하고 자동으로 넘어가지 않는다.

1. ① QR 입력: Pi 화면의 QR을 스캐너로 찍으면 기기 정보가 채워진다 (한글 입력 상태여도 같음). QR이 없으면 「직접 입력」으로 손으로 채우거나 비워 둔 채 넘어간다 (FR-Q-01~05).
2. ② CSV 넣기: CSV 6개를 한 번에 끌어다 놓거나 고른다. 파일마다 한 줄에 판별 결과·행 수·근거가 보이고 틀리면 목록에서 바꾼다 (「수동」 표시). 개수·중복·못 읽는 파일은 「다음」을 잠근다. QR과 CSV의 모델·제조번호·최대 측정범위가 다르면 노란 경고와 「그래도 진행」이 나온다 (FR-F-04·05, FR-X-01).
3. ③ 계산 확인: 종합판정, 카드 3개, 장비 정보 두 묶음, 모달 버튼 3개를 본다 (FR-M4-09, FR-M4-12~15).
4. ④ 저장: CSV에 없는 일반사항 값 13칸을 넣고(모두 선택) 「Excel 저장」을 누르면 저장 위치를 골라 저장한다. 같은 이름이 있으면 덮어쓰기를 확인한다 (FR-M5-05, FR-S-01~05).

V3(2026-10-22)의 2화면(결과·저장) 설명은 이 4단계로 대체되었다. 이 문서에서 「결과 화면」은 ③, 「저장 화면」은 ④다.

### FR-M4-11 수락 기준 (CWS-36, v2 시안 기준)

근거 화면은 `design/mockup-toss-v2.html`이다. 시안에 없는 상태(검증 오류, 알림, 경고, 저장 막힘 중 CSV 문제)는 Frontend가 같은 디자인 언어로 구현하고, 아래의 기능 동작만 지킨다. 문구의 모양·색·위치의 시각 부분은 UX Designer 몫이다.

- AC-1 (정상) **[대체됨(팀 기준, 2026-10-29) → AC-36]** Given 견본 6개 또는 직접 고른 6개가 검증을 통과했을 때, When 화면을 보면, Then 화면이 바뀌지 않고 같은 화면에서 왼쪽 패널에 6칸 모두의 칸 이름(반복성·직선성·설치방향 민감도 × 요약·source)과 파일 이름이 보이고, 자동 배정된 칸에는 「자동」 표시가 있으며, 오른쪽에 결과가 나타난다. 사용자가 직접 바꾼 칸은 「자동」과 구분되게 표시한다.
- AC-2 (칸 펼치기·바꾸기) **[대체됨(팀 기준, 2026-10-29) → AC-36]** Given 결과가 나온 화면일 때, When 칸 하나를 누르면, Then 그 칸이 펼쳐져 「이 칸에 넣을 파일 (바꾸기)」 목록과 「판별 근거: 측정점 N개, 패턴 → 종류」가 보인다. 목록에서 다른 파일을 고르면 화면 이동 없이 다시 검증·계산해 결과가 바뀌고, 키보드 초점은 그 목록에 남는다. 넣었던 파일은 다시 넣지 않아도 유지된다.
- AC-3 (실패) **[일부 대체됨(팀 기준, 2026-10-29): 「Excel 만들고 저장」 비활성은 ②의 「다음」 잠김으로 바뀜, AC-28·AC-37. 나머지는 유지]** Given 검증 오류가 있을 때, When 화면을 보면, Then 결과는 나오지 않고 오류 메시지(문제 파일, 행, 이유)가 보이며, 6칸 배정과 판별 근거는 그대로 보인다. 「Excel 만들고 저장」 버튼은 비활성이다.
- AC-4 (알림·경고) Given 판별 불가 파일이 섞여 있어도 6칸이 모두 차서 결과가 만들어졌거나 경고(PAIR_TIME 등)가 있을 때, When 화면을 보면, Then 「알림 N건」, 「경고 N건」과 그 내용(파일 이름 포함)을 같은 화면에서 결과를 가리지 않고 볼 수 있다. 알림이 있는데 표시가 없으면 실패다 (단계 3 리뷰 중요 1과 같은 기준).
- AC-5 (좁은 화면) Given 폭 390 px에서, When 화면을 보면, Then 패널과 결과가 세로로 쌓여도 가로 스크롤이 없고, 위 줄의 저장 버튼이 보이고 눌린다.
- AC-6 (안내 문구) **[일부 대체됨(팀 기준, 2026-10-29): 「단계 탭은 없고 … 이동 버튼은 AC-24의 두 개뿐이다」 부분은 AC-27·AC-28로 바뀜. 방향 말 금지와 자동 이동 문장 금지는 유지]** Given 파일을 넣기 전과 후에, When 안내를 보면, Then 「검증을 통과하면 결과가 바로 나타납니다」(빈 화면에서는 「…결과가 이 화면에 바로 나타납니다」)라는 문장이 있고 「오른쪽」·「왼쪽」 같은 방향 말은 쓰지 않으며(390 px에서는 패널과 결과가 세로로 쌓이므로 폭과 상관없이 맞는 말만 쓴다), 「자동으로 결과 확인 화면으로 이동합니다」 같은 이동 문장은 없다. 단계 탭은 없고, 화면 사이의 이동 버튼은 AC-24의 두 개뿐이다 (V3 수정).
- AC-7 (결과 표시 낭독, A6) **[일부 대체됨(팀 기준, 2026-10-29): 「화면 이동이 없으므로 초점을 옮기지 않는다」 부분은 AC-29로 바뀜. 낭독 문구는 ③에 들어올 때 AC-29와 함께 나온다]** Given 검증을 통과해 결과가 나타났을 때, When 표시가 끝나면, Then 상태 알림 영역(`role="status"`, `aria-live="polite"`)에 「6개 파일을 칸에 배정하고 검증을 통과해 결과를 표시했습니다.」가 나온다. 경고나 알림이 있으면 같은 문장 끝에 0건이 아닌 쪽만 붙인다: 경고만 있으면 「경고 N건이 있습니다.」, 알림만 있으면 「알림 N건이 있습니다.」, 둘 다 있으면 「경고 N건, 알림 N건이 있습니다.」 (「경고 0건」처럼 0건은 읽지 않는다). 화면 이동이 없으므로 키보드 초점은 옮기지 않고 사용자가 있던 자리에 둔다. 같은 동작을 연달아 두 번 해도(견본 두 번 누름) 두 번 모두 낭독되고, 새 파일을 넣으면 이전 문구는 새 문구로 바뀐다.
- AC-9 (오류·배정 변경 낭독) Given 검증 오류가 생겼을 때, When 화면이 갱신되면, Then 상태 알림 영역에 「오류 N건이 있습니다. 오류 내용을 확인하세요.」가 나온다 (화면 폭에 따라 오류 내용이 오른쪽이 아니라 아래에 쌓이므로 방향 말은 쓰지 않는다). Given 칸의 파일을 바꿔 다시 검증했을 때, Then 통과하면 AC-7 문구를, 오류가 있으면 이 문구를 다시 낭독한다 (이전과 같은 문구여도 낭독).
- AC-10 (막힘 상자 문구, RC P3-2) Given 검증 오류로 결과와 Excel을 만들 수 없을 때, When 막힘 상자를 보면, Then 문구는 「검증을 통과하지 못해 결과와 Excel을 만들 수 없습니다. 「넣은 파일」 칸에서 오류를 고쳐 주세요.」이다. 패널 이름 「넣은 파일」로 위치를 가리키고 「왼쪽」 같은 방향 말은 쓰지 않는다. 화면의 안내·막힘·오류 문구 전체가 같은 규칙이다 (이 문서 3절 AC에서 「왼쪽」·「오른쪽」은 넓은 화면의 배치 설명일 뿐 화면 문구가 아니다).
- AC-11 (선택 입력 오류 표시, RC P3-3, V3에서 고침) V2의 접힘·자동 열림 동작은 없어졌다(저장 화면에는 접는 영역이 없다). 남은 기준: Given 저장 화면에서 입력 칸에 잘못된 값(예: 피토계수 `abc`)이 들어가 오류가 생기면, Then 입력 영역 제목 옆에 「고칠 곳 1건」 배지가 보이고, 저장 버튼이 비활성이 되며, 위 줄 아래에 막힘 안내와 「고칠 칸으로」 링크가 나온다. 링크를 누르면 초점이 첫 오류 칸으로 간다. 오류를 고치면 배지와 막힘 안내가 사라지고 저장 버튼이 켜진다. 자세한 문구는 FR-M5-05, FR-M5-06, AC-22.
- AC-8 (결과 순서) Given 결과가 나온 화면일 때, When 위에서부터 보면, Then 종합판정 줄(적합/부적합, 현장적용계수 「해당없음」)이 맨 위, 그 아래 항목 카드 3개가 가로로, 그 아래 장비 정보 두 묶음, 그 바로 아래 모달 버튼 3개 한 줄(「설치 방향 및 민감도 그래프, 시험 환경 조건」, 「CLAYDOX가 가져갈 주요 셀」, 「계산에 쓴 행」 순서) 순서다. 본문에 그래프, 환경 조건, 주요 셀 표, 계산에 쓴 행 표는 없다. 1366×768 화면의 첫 화면에 종합판정 줄·카드 3개·장비 정보 두 묶음·버튼 줄이 모두 보인다 (AC-14, 요소의 `bottom <= 768`).

UIUX_REVIEW U1과 같은 방침. 키보드로 Tab 해서 닿는 버튼·입력 칸의 초점 표시는 그대로 둔다). 상태 알림 영역(`role="status"`)에 「Excel 저장 화면입니다. 일반사항 값은 모두 선택이며 비워도 저장할 수 있습니다.」를 한 번 낭독한다. 「뒤로」로 돌아오면 초점은 「Excel 만들고 저장」 버튼으로 가고 「결과 화면으로 돌아왔습니다.」를 낭독한다. 같은 이동을 연달아 두 번 해도 두 번 낭독한다 (AC-7과 같은 방식). |
| 4 | AC-11 처리 | 접는 영역이 없으므로 AC-11을 위 3절 문구로 고쳤다 (접힘·자동 열림 삭제, 「고칠 곳 N건」 배지·막힘 안내·「고칠 칸으로」 링크·초점 이동은 유지). 없애지 않았다. |
| 5 | 브라우저 뒤로 가기 (AC-23) | 지원하지 않는다. 화면 안 「뒤로」 버튼만으로 돌아온다. 화면을 옮겨도 브라우저 이력(history)을 쌓지 않는다. 이유: 데이터를 저장하지 않는 도구라 실수로 이력을 거슬러 가면 입력이 사라질 수 있고, `file://` 환경에서 이력을 다루는 것은 이 도구의 범위를 키운다. 브라우저 뒤로 가기는 지금처럼 도구 페이지를 떠난다. |

**모달 공통 규칙 (AC-18)**: 대상은 「설치 방향 및 민감도 그래프, 시험 환경 조건」 모달, 「CLAYDOX가 가져갈 주요 셀」 모달, 「계산에 쓴 행」 모달 3개다 (제목은 각 버튼 문구와 같다).

- 구조: `role="dialog"`(또는 `<dialog>`), `aria-modal="true"`, 제목을 `aria-labelledby`로 가리킨다. 닫혀 있을 때는 화면과 접근성 트리에 내용이 없다.
- 열기: 버튼을 누르거나 키보드(Enter·Space)로 연다. 열면 초점은 모달 제목으로 간다 (큰 테두리 없음).
- 닫기 수단은 닫기 버튼과 Esc 두 가지다. 배경을 눌러도 닫히지 않는다 (실수 방지). 닫으면 초점이 그 모달을 연 버튼으로 돌아간다.
- 초점 가두기: Tab·Shift+Tab은 모달 안에서만 돈다. 열려 있는 동안 뒤 화면은 조작되지 않고 스크롤도 되지 않는다.
- 폭 390 px에서도 모달이 화면 안에 들어오고 모달 안쪽에서 세로로 스크롤한다. 페이지 가로 스크롤은 없다 (표가 넓으면 표 안쪽 가로 스크롤만 허용).
- 모달을 열고 닫는 것은 계산·검증을 다시 하지 않는다.

**저장 화면 규칙**

- 저장 화면에는 넣은 파일 패널·결과·종합판정이 보이지 않는다 (상태는 보존). 견본 표시줄(견본 데이터 안내)과 위 줄은 계속 보인다.
- 저장 화면에서 파일을 새로 넣을 수는 없다. 새 CSV는 결과 화면에서만 넣는다.
- 저장 화면에서 「Excel 저장」을 누르면 파일을 내려받고, 저장 화면에 그대로 머문다.

**수락 기준**

- AC-12 (장비 정보 두 묶음) Given 결과가 나온 화면일 때, When 장비 정보를 보면, Then 묶음 「장비」(라벨 순서: 모델명, 기기번호, 최대유속, 기기 종류)와 묶음 「접수」(접수번호, 의뢰기관, 주소, 시험일자)가 있고 값은 V2와 같다 (최대유속은 `N m/s`). 확인: 견본으로 결과를 띄워 묶음 2개, 묶음별 라벨 4개와 순서를 e2e로 본다.
- AC-13 (묶음 제목·좁은 화면) Given 위 화면일 때, Then 묶음 제목은 「장비」·「접수」이고 화면 글자에 「왼쪽」·「오른쪽」이 없다. 폭 390 px에서 두 묶음이 세로로 쌓여도 `scrollWidth <= clientWidth`다.
- AC-14 (첫 화면) Given 1366×768에서 결과가 나온 화면일 때, Then 종합판정 줄, 카드 3개, 장비 정보 두 묶음, 그 바로 아래 모달 버튼 3개 한 줄(「설치 방향 및 민감도 그래프, 시험 환경 조건」, 「CLAYDOX가 가져갈 주요 셀」, 「계산에 쓴 행」)이 모두 보인다 (각 요소와 버튼 3개 모두 `bottom <= 768`). 이 위치는 54fbe8d의 「장비 정보 제목 줄 오른쪽」을 사용자 요청으로 대체한다. 확인: 1366×768에서 버튼 줄이 장비 정보 두 묶음 아래에 있고 버튼 3개의 `top`이 같은 줄(차이 < 버튼 높이)이며 `bottom <= 768`인지 검사한다. 못 맞추면 Frontend가 실측값(버튼 줄 bottom px)을 god에게 알린다. AC-14를 고칠지(예: 버튼 줄만 첫 화면 밖 허용)는 사람이 정하고, 그 결정 전에는 이 기준을 바꾸지 않는다.
- AC-15 (모달 버튼 3개) Given 결과가 나온 화면일 때, Then 본문에 「설치방향 민감도 그래프」·「시험 환경 조건」 제목, 주요 셀 표, 「계산에 쓴 행」 표 3개(반복성·직선성·설치방향 민감도)가 없고, 「설치 방향 및 민감도 그래프, 시험 환경 조건」 버튼이 하나 있다 (Tab으로 닿고 Enter·Space로 열림). 이 화면의 모달은 그래프·환경 조건(AC-16), 주요 셀(AC-17), 계산에 쓴 행(AC-26) 3개이고 버튼도 3개다. 확인: 모달이 닫힌 상태에서 위 제목·표가 본문에 없고 모달 버튼이 3개인지 e2e로 본다.
- AC-16 (그래프·환경 조건 모달) When 그 버튼을 누르면, Then 모달이 뜨고 30 %·70 % 그래프 2개와 환경 조건 표(대기압·온도·습도 3행, 최소·최대·중간값)가 나온다. 그래프(기준선 4 %, 최대점 빨강)와 숫자는 V2 화면과 같다.
- AC-17 (주요 셀 모달) Given 결과 화면 또는 저장 화면일 때, When 「CLAYDOX가 가져갈 주요 셀」 버튼을 누르면, Then 모달에 주요 셀 표 23행과 「숫자는 앞 10자리까지」 안내가 V2와 같이 나온다. 이 버튼은 각 화면에 하나씩 있다 (결과 화면에서는 장비 정보 두 묶음 아래 버튼 줄 안, 저장 화면에서는 그대로). 닫으면 초점이 누른 버튼으로 돌아간다. 확인: 두 화면 각각에서 e2e로 모달 안 표 23행을 검사한다. 표의 값은 여는 시점의 입력값을 반영한다 (저장 화면에서 피토계수를 넣은 뒤 열면 그 값이 보임).
- AC-18 (모달 접근성) 위 「모달 공통 규칙」을 모달 3개 각각에서 만족한다. 확인: 열기 → Tab 반복해도 초점이 모달 안 → Esc → 초점이 연 버튼. axe 위반 0건.
- AC-19 (저장 화면으로 넘어감) **[대체됨(팀 기준, 2026-10-29) → AC-28]** Given 결과가 나온 화면일 때, When 「Excel 만들고 저장」을 누르면, Then 다운로드가 일어나지 않고 저장 화면으로 넘어가 입력 칸 13개와 「Excel 저장」 버튼이 보인다. 결과가 없거나 CSV 검증 오류가 있으면 「Excel 만들고 저장」은 비활성이다 (AC-3).
- AC-20 (저장 화면 초점·낭독) **[대체됨(팀 기준, 2026-10-29) → AC-29]** When 저장 화면으로 넘어가면, Then 초점은 제목 「Excel로 저장」에 있고 큰 초점 테두리는 없으며, 상태 알림 영역에 위 확정 3의 문구가 한 번 낭독된다.
- AC-21 (입력은 모두 선택) 13칸이 모두 비어 있어도 「Excel 저장」으로 저장된다. 파일 이름과 셀 값은 V2 빌드와 같다 (비운 칸은 「-」 또는 양식 그대로). 확인: 빈 입력으로 저장한 파일과 V2 빌드로 저장한 파일의 셀 값 비교.
- AC-22 (입력 검증·오류) Given 저장 화면에서 잘못된 값(예: 피토계수 `abc`)이 있을 때, Then 「Excel 저장」이 비활성이고, 「입력 값에 고칠 곳이 있어 저장할 수 없습니다. 표시된 칸을 고치면 저장할 수 있습니다.」와 「고칠 칸으로」 링크, 제목 옆 「고칠 곳 N건」, 칸 아래 「{항목 이름}{은/는} …입력하세요.」, `aria-invalid="true"`·`aria-describedby`가 나온다. 입력 칸은 처음부터 펼쳐져 있다. 규칙과 문구는 V2와 같다. 기존 AC-11·FR-M5-06 시험은 저장 화면 기준으로 고친다.
- AC-23 (뒤로) **[대체됨(팀 기준, 2026-10-29) → AC-30]** Given 저장 화면에서 값을 입력했을 때, When 「뒤로」를 누르면, Then 결과 화면이 그대로 나온다 (6칸 배정, 결과, 칸에서 바꾼 파일, 열려 있던 칸). 다시 「Excel 만들고 저장」으로 오면 입력했던 값이 남아 있다. 브라우저 뒤로 가기는 지원하지 않는다 (이력을 쌓지 않음).
- AC-24 (이동 버튼 두 개) **[대체됨(팀 기준, 2026-10-29) → AC-27, AC-28]** 결과 화면에서 저장 화면으로 가는 길은 「Excel 만들고 저장」 하나, 돌아오는 길은 「뒤로」 하나다. 단계 탭은 없고 「자동으로 … 이동합니다」 같은 문장도 없다. 확인: 화면 글자 검사와 이동 버튼 2개(앞·뒤)만 있는지 e2e.
- AC-26 (계산에 쓴 행 모달, V3-C+) Given 결과가 나온 화면일 때, When 버튼 줄의 「계산에 쓴 행」을 누르면, Then 모달이 떠서 표 3개를 같은 내용·순서로 보여준다. 순서는 반복성: 요약 CSV 값 → 직선성: 요약 CSV 값 → 설치방향 민감도: 그룹별 값이고, 열 이름과 행 값도 이 변경 전과 같다. 본문의 「계산에 쓴 행 보기」 접기 영역은 없다. 접근성은 AC-18과 같다 (열면 초점이 모달 안, 초점 가둠, Esc·닫기 버튼, 닫으면 눌렀던 「계산에 쓴 행」 버튼으로 초점 복귀, `aria-modal`). 390 px에서 표가 넓으면 표 안쪽 가로 스크롤만 허용한다. 확인: e2e로 견본에서 모달 안 표 3개의 제목 순서와 행 수가 이 변경 전 빌드와 같은지 검사한다. 계산·판정·Excel 셀 값은 불변이다.
- AC-25 (판정 카드 칸 색, V3-C) Given 결과가 나온 화면일 때, Then 카드 3개의 칸 색은 각 카드의 판정을 따른다. (a) 세 항목이 모두 적합인 견본이면 세 카드 모두 종합판정 줄의 적합 색과 같다 (테두리·배경의 계산된 색이 같음). (b) 한 항목만 부적합인 데이터이면 그 카드만 종합판정 줄의 부적합 색과 같고 나머지 카드는 적합 색이다. (c) 어느 경우에도 카드의 「적합」·「부적합」 글자는 그대로 보이고, 카드 글자와 배경의 대비는 4.5:1 이상이다. (d) 카드 값, 판정, 종합판정, Excel 셀 값은 이 변경 전과 같다. 확인: e2e에서 견본(전부 적합)과 한 항목만 기준을 넘도록 만든 입력(예: 판정 기준만 좁힌 설정 또는 부적합 시험용 CSV)으로 카드와 종합판정 줄의 계산된 테두리·배경색을 비교하고, 대비 비율을 계산해 4.5 이상인지 본다.

| 업체명 | `cn` | 「업체명은 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | 앞뒤 공백을 지운 뒤 1자 이상 | (없음, 비었을 때만 오류) |
| 모델 | `md` | 「모델은 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | 앞뒤 공백을 지운 뒤 1자 이상 | (없음) |
| 제조번호 | `sn` | 「제조번호는 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | 앞뒤 공백을 지운 뒤 1자 이상. 안의 공백은 그대로 둔다 (예: `SN 55/7`) | (없음) |
| 접수번호 | `rn` | 「접수번호는 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | `NN-NNNNNN-NN` (숫자 2-6-2자리, 하이픈 포함) | 「접수번호는 25-123456-01처럼 숫자 2자리-6자리-2자리로 입력하세요.」 |
| 형식승인번호 | `ap` | 「형식승인번호는 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | 앞뒤 공백을 지운 뒤 1자 이상 | (없음) |
| 최대 측정범위 | `rg` | 「최대 측정범위는 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」 | 0보다 큰 수 (단위 m/s는 칸 옆 글자) | 「최대 측정범위는 0보다 큰 숫자로 입력하세요.」 |

오류는 그 칸을 떠날 때와 「다음」이 잠긴 상태에서 칸을 고칠 때 칸 아래에 보인다. 오류 칸은 `aria-invalid="true"`와 `aria-describedby`로 문구에 연결하고 색과 함께 문구를 쓴다. 칸 오류 문구는 `role="alert"`를 쓰지 않는다 (①에서 `role="alert"`는 QR 입력칸 오류 하나만, UI 규격). 「다음」이 잠긴 이유 한 줄 「기기 정보를 모두 입력하거나 모두 비워야 넘어갈 수 있습니다.」는 `role="status"`로 낭독한다.

| ② | 그래도 진행 | 교차 확인에서 다른 항목이 있음 (이때 「다음」은 잠김) | ③ |

**수락 기준 (팀 기준)**

- AC-27 (단계 표시) Given 도구를 처음 열었을 때, Then 단계 목록에 「QR 입력」·「CSV 넣기」·「계산 확인」·「저장」 4개가 이 순서로 번호와 함께 있고, 현재 단계는 글자 또는 아이콘으로도 구분되며(색만으로 구분하지 않음) `aria-current="step"`이 걸려 있다. 처음 단계는 ①이고 초점은 QR 입력칸에 있다. 단계 목록 항목을 눌러도 이동하지 않는다. 확인: e2e로 항목 4개의 이름·순서, `aria-current`, `document.activeElement`를 검사한다.
- AC-28 (다음·잠김) Given 각 단계에서, Then 「다음」은 위 「단계 상태 전이」 표의 조건에서만 켜진다. ②에서 6종류가 안 채워졌거나 같은 종류가 2개이거나 검증 오류가 있으면 「다음」이 잠기고 이유가 보인다. ③에서는 항상 켜져 있다. ④에는 「다음」이 없다. 「Excel 만들고 저장」 버튼은 없다. 자동으로 넘어가지 않고 「자동으로 … 이동합니다」 같은 문장도 없다. 확인: e2e로 단계마다 버튼의 활성 여부와, 파일을 다 넣어도 사람이 누르기 전에는 ②에 머무는지 검사한다.
- AC-29 (단계 진입 초점·낭독) When 단계가 바뀌면, Then 초점이 새 단계 제목에 가고(큰 초점 테두리 없음, UIUX_REVIEW U1) 상태 알림에 한 번 낭독된다. ②: 「4단계 중 2단계, CSV 넣기 화면입니다.」 ③: 「4단계 중 3단계, 계산 확인 화면입니다. 6개 파일을 칸에 배정하고 검증을 통과해 결과를 표시했습니다.」에 AC-7의 경고·알림 끝말을 붙인다. ④: 「4단계 중 4단계, 저장 화면입니다. 일반사항 값은 모두 선택이며 비워도 저장할 수 있습니다.」 같은 이동을 연달아 두 번 해도 두 번 낭독한다. 확인: e2e로 `document.activeElement`와 `role="status"` 문구를 검사한다.
- AC-30 (뒤로) Given ②~④의 어느 단계에서, When 「뒤로」를 누르면, Then 바로 앞 단계가 입력·배정·결과 그대로 보인다 (QR 값, 「수동」으로 바꾼 줄, 열려 있던 모달 버튼 상태 포함). 초점은 그 단계에서 앞으로 가던 버튼(「다음」 또는 「그래도 진행」)에 가고 「4단계 중 N단계, {이름} 화면으로 돌아왔습니다.」를 낭독한다. ①에는 「뒤로」가 없다. 다시 앞으로 오면 ④의 입력값이 남아 있다. 새 CSV를 넣으면 ④의 입력값은 비워진다 (FR-M5-05). 확인: e2e로 값 입력 → 뒤로 → 앞으로 → 값이 그대로인지 검사한다.
- AC-31 (QR 정상, 벡터 valid 3개) Given ①에서, When 벡터의 유효 QR 3개를 각각 입력하고 Enter를 누르면, Then 1초 안에 기기 정보 칸이 벡터 `input`과 같은 값(접수번호, 모델, 제조번호, 형식승인번호, 최대 측정범위, 업체명=`company`)으로 채워지고, 초록 체크와 「QR 확인됨」(아이콘과 글자)이 보이고, 입력 출처가 「QR」이다. 확인: 벡터 파일의 `valid: true` 3개를 단위 시험과 e2e로 돌린다 (ktl-flow-pc #3의 「테스트 벡터 전부」).
- AC-32 (QR 거부, 벡터 invalid 2개) When 벡터 4(체크값 불일치)를 입력하면, Then 입력칸에 빨간 테두리와 오류 아이콘이 보이고 「QR을 다시 스캔하세요」가 보이며 입력칸이 비워진다. 이미 확인된 기기 정보가 있었다면 바뀌지 않는다. When 벡터 5(`v`=2)를 입력하면, Then 「Pi 프로그램과 버전이 다릅니다」가 보이고 입력칸이 비워진다. 두 경우 모두 상태 알림이 그 문구를 낭독한다. 확인: 벡터 `valid: false` 2개를 돌려 기대 문구와 같은지 본다.
- AC-33 (한/영 같은 결과) Given 벡터 유효 QR 3개(대문자가 섞인 `cn` `6rCA64KY64uk7YWM7YGsKOyjvCk` 포함)를, When 한글 입력 상태와 영문 입력 상태에서 같은 물리 키 순서로 입력하면(키 입력의 `event.code`와 Shift 상태로 두 상태를 만든다), Then 두 상태의 결과가 같다 (AC-31과 같은 값). 무효 벡터 2개도 두 상태에서 같이 거부된다. 확인: e2e로 두 상태를 흉내 낸다. 실제 한글 입력기와 실제 스캐너는 사람이 확인한다 (`planning/HUMAN_CHECKS.md`).
- AC-34 (QR 형식 오류) Given ①에서, When JSON이 아닌 글자, 키가 빠진 QR, `rn` 형식이 틀린 QR, `rg`가 숫자가 아닌 QR, `cn`이 Base64가 아닌 QR을 입력하면, Then 「QR을 읽을 수 없습니다. 다시 스캔하거나 직접 입력하세요.」가 보이고 입력칸이 빨간 테두리와 함께 비워진다. 기기 정보는 바뀌지 않는다. 확인: 5가지 입력을 각각 시험한다.
- AC-35 (직접 입력) Given ①에서, When 「직접 입력」을 누르면, Then 6칸(업체명, 모델, 제조번호, 접수번호, 형식승인번호, 최대 측정범위)이 나오고 첫 칸에 초점이 가며, 채운 값의 출처는 「수동」이다. (a) 6칸을 모두 올바르게 채우면 「다음」이 켜진다. (b) 6칸을 모두 비우면 「다음」이 켜진다 (기기 정보 없음). (c) 일부만 채웠으면 「다음」이 잠기고 빈 칸 아래에 「{칸 이름}{은/는} 비워 둘 수 없습니다. 모든 칸을 채우거나 모두 비우세요.」가 보이고 「기기 정보를 모두 입력하거나 모두 비워야 넘어갈 수 있습니다.」가 낭독된다. (d) 접수번호 `12-34`처럼 형식이 틀리면 칸 아래에 직접 입력 칸 표의 문구가 `aria-invalid`와 함께 보이고 「다음」이 잠긴다. 최대 측정범위가 0 이하이거나 숫자가 아니어도 같다. 제조번호 `SN 55/7`처럼 안에 공백이 있는 값은 올바른 값이다. (e) 「QR 스캔으로」를 누르면 쓴 값이 버려지고 직접 입력을 열기 전 상태가 된다. 확인: e2e로 (a)~(e)를 각각 시험하고, 올바른 입력의 값이 QR로 채운 것과 같은 형태로 다음 단계에 넘어가는지 본다.
- AC-36 (파일 줄) Given ②에서 CSV 6개(견본 또는 합성 CSV)를 넣었을 때, Then 파일마다 한 줄에 파일 이름, 판별 결과, 행 수, 판별 근거가 보이고, 자동 판별된 줄은 「자동」이다. When 한 줄의 목록에서 종류를 바꾸면, Then 그 줄만 「수동」으로 바뀌고 화면 이동 없이 다시 검증된다. 확인: e2e로 줄마다 4가지 값과 표시를 검사한다.
- AC-37 (파일 예외) Given ②에서, When 파일이 6개가 아니거나, 같은 종류가 2개이거나, 종류가 빠졌거나, 읽을 수 없는 파일이 있으면, Then 빠진 종류와 중복 종류가 빨간 줄(글자 포함)로 보이고 「다음」이 잠긴다. 읽을 수 없는 파일의 줄에는 「풍동 CSV 형식이 아닙니다」가 보인다. 검증 오류가 있으면 AC-3·AC-10대로 결과가 안 나오고 「다음」이 잠긴다. 확인: 5가지 경우(5개만, 같은 종류 2개, 빠진 종류, 못 읽는 파일, 검증 오류)를 e2e로 시험한다.
- AC-38 (판별 정확) Given 견본 6개의 파일 이름을 바꾸고 순서를 섞어 넣었을 때, Then 6종류가 모두 맞게 판별되고 근거 문구가 줄마다 나온다. 확인: 기존 판별 시험을 그대로 돌리고, 합성 CSV 세트(#2)가 생기면 같은 시험을 합성 세트로 한 번 더 돌린다.
- AC-39 (교차 불일치) Given 기기 정보가 있고 ②의 CSV 6개가 검증을 통과했을 때, When 모델이 다르면(예: QR `FM-100`, CSV `FM-10O`) ②의 「다음」을 눌러 보면, Then 노란 경고(아이콘과 글자)에 다른 항목마다 한 줄로 「모델 — QR: FM-100 / CSV: FM-10O」가 보이고, 「다음」은 잠기고 「그래도 진행」이 있다. 「그래도 진행」을 누르면 ③으로 가고 ③에 「QR과 CSV 값이 다릅니다 (확인함)」 한 줄이 남는다. 제조번호, 최대 측정범위가 다른 경우도 같다. 계산·판정·Excel 셀 값은 같다. 확인: 항목 3개를 각각 어긋나게 만든 입력으로 e2e를 돌린다.
- AC-40 (교차 일치·기기 정보 없음) Given 기기 정보의 세 값이 CSV와 같을 때(`rg`는 22와 22.0 포함), Then 경고가 없고 「다음」이 켜진다. Given ①에서 기기 정보를 넣지 않았을 때, Then 비교하지 않고 경고도 없다. Given 직접 입력(수동) 값이 CSV와 다를 때, Then 노란 경고가 QR과 같게 나온다. 확인: e2e로 세 경우를 시험한다.
- AC-41 (저장 위치 선택) Given ④에서 선택 입력 오류가 없을 때, When 「Excel 저장」을 누르면, Then 저장 위치 선택 창이 열리고 제안 이름은 `{접수번호} {회사명} CLAYDOX.xlsx`이다. 위치를 고르면 그 위치에 파일이 만들어지고 내용은 AC-21과 같다. 확인: e2e는 선택 창을 가짜 핸들로 바꿔 쓰인 바이트의 셀 값을 비교한다. 실제 선택 창은 사람이 Chrome과 Edge에서 확인한다 (비교 3절, 비교 6절 가정).
- AC-42 (덮어쓰기) Given 같은 이름 파일이 있는 위치를 골랐을 때, Then 사용자 동의 없이 그 파일이 바뀌지 않는다. 「덮어쓰기」를 고르면 바뀌고 「다른 이름」을 고르면 원본은 그대로이고 새 파일이 `_2`가 붙은 이름으로 만들어진다 (앱이 알 수 있는 방식일 때, 사용자 결정 대기). 확인: 같은 이름 파일을 미리 두고 두 선택지를 시험한다.
- AC-43 (저장 완료·폴더 열기) When 저장이 끝나면, Then 「{파일 이름}을 저장했습니다.」가 상태 알림과 화면에 보이고 ④에 머문다. HTML 가정에서는 「폴더 열기」 단추가 없다 (**사용자 결정 대기**). 확인: e2e로 문구와 단추 없음을 검사한다. exe로 정해지면 단추가 있고 누르면 저장한 폴더가 열려야 한다.
- AC-44 (저장 취소·실패·대체) When 저장 위치 선택 창을 닫으면, Then 파일이 만들어지지 않고 「저장을 취소했습니다.」가 보이며 ④에 머문다. When 쓰기가 실패하면, Then 「파일을 저장하지 못했습니다. 다른 위치를 골라 다시 저장하세요.」가 보이고 「Excel 저장」이 다시 켜져 있다. Given 브라우저가 저장 위치 선택을 지원하지 않을 때, Then 브라우저 다운로드로 저장된다. 확인: 가짜 핸들이 취소 오류, 쓰기 오류를 내도록 해서 e2e로 시험하고, 선택 창 함수를 지운 상태로 다운로드 이벤트를 시험한다.
- AC-45 (실행 형태, HTML 가정) Given 빌드된 HTML 파일 하나를, When 새 PC의 Windows Chrome 또는 Edge에서 더블클릭하면, Then ①이 열리고 ④까지 동작하며 외부 요청이 0건이다. 확인: `check-dist`와 e2e로 요청 수 0을 검사하고, 실험 PC에서는 사람이 확인한다 (`planning/HUMAN_CHECKS.md`). exe 형태는 **사용자 결정 대기**다.
