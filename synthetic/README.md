# 합성 풍동 CSV — 이슈 #2

이 폴더의 CSV와 정답은 **모두 코드로 새로 만든 가짜 값**이다. 제공된 연구원 견본은 실제 견본으로 취급하며 저장소 밖에 둔다. 생성기는 원본 견본·프로토타입을 읽지 않는다. 실제 견본에서는 칼럼명·단위·행 배치만 확인했고, 측정값·업체·주소·기기 식별자는 옮기지 않았다.

## 생성·확인

```powershell
python synthetic/generate.py
python synthetic/generate.py --check
python -m pytest -q tests/test_synthetic.py
```

Python 표준 라이브러리만으로 생성한다. 테스트에는 `python -m pip install pytest==9.2.0`이 필요하다. 생성물은 기본적으로 이 폴더 아래에 쓰며, `--output <폴더>`로 별도 합성 출력 위치를 지정할 수 있다. 같은 입력 파라미터에서는 바이트 단위로 재현된다. `--check`는 파일을 수정하지 않고 누락·변경을 검출한다.

## 두 세트의 차이

| 세트 | 최대 유속 | 날짜 표기 | 12행 칼럼명 | 정답 특징 |
|---|---|---|---|---|
| set_a | 20 m/s | MM-DD-YYYY | `측정 유속`, `압 력` 등 원래 공백 | 양·음 오차가 상쇄되는 직선성, 민감도 2% |
| set_b | 30 m/s | YYYY-MM-DD | 공백 제거 | 직선성 음의 평균 오차, 민감도 4.8%, 더 큰 반복성 |

MM-DD-YYYY는 제공 견본에서 확인한 source 표기이며, YYYY-MM-DD는 날짜 2형식 요구를 검증하기 위한 합성 변형이다. 날짜 단위 행도 각 표기에 맞춘다. 실제 장비의 모든 출력 형식이라고 주장하지 않는다.

각 세트에는 중립적인 이름의 CSV 6개와 `expected.json`이 있다. 종류를 파일명으로 추측하지 않도록 순서도 결과/source 순으로 맞추지 않았다. 정답 JSON의 `files`에는 종류·데이터 행 수·SHA-256을 기록한다.

- 1~11행: 같은 세트의 가짜 기기 정보. 값은 `SYNTHETIC-ONLY`와 `SYNTH-*` 식별자로 구분한다.
- 12행: 결과 11열(`저장번호` 시작), source 10열(`시험번호` 시작).
- 13행: 단위. 14행부터 결과 10/10/30행, source 50/50/150행.
- 인코딩은 cp949, 줄 끝은 CRLF, BOM은 없다.
- 각 결과 행에 source 5행이 대응한다. 기준유속은 같고 측정유속 5개 평균이 결과 측정유속과 같다.
- 반복성 기준은 최대의 9%/80% 교대, 직선성은 30% 5행 뒤 70% 5행이다. 민감도는 각도 0, -10, -5, +5, +10 순으로 각 30%·70%의 3행 묶음이다.

## 계산 정답

`expected`의 수치는 결과 CSV만으로 계산하는 정답이며 백분율 단위다. JSON 숫자는 반올림하지 않고, 테스트에서는 소수 셋째 자리 정확도(절대 오차 0.0005 이내)를 검증한다. 생성기는 선택한 파라미터의 해석식으로 정답을 만들고, 테스트는 저장된 CSV에서 독립적으로 다시 계산한다.

- 반복성: 결과 행의 ZERO/SPAN 각각 표본표준편차(n-1) / 최대 유속 × 100. 모집단표준편차가 아니다.
- 직선성: 두 5행 묶음별 ① 상대오차 절댓값의 최댓값 ② 평균 측정값과 평균 기준값의 차이 비율을 모두 제공한다. ②는 계약의 부호를 유지한다.
- 민감도: 3행씩 평균한 오차의 절댓값 중 최댓값이다. 개별 행의 최댓값과 구별되는 데이터다. 10개 묶음의 각도·범위·평균 오차도 기록한다.

제품 CSV 파서·계산 UI·Excel 출력은 이 이슈에서 구현하지 않는다. 이 데이터는 후속 파서·계산·출력 테스트의 입력과 기준으로 사용한다.
