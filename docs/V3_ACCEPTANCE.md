# V3 화면 흐름 변경 수락 기준 (사람 요청 4건)

작성 2026-10-22 · Product Owner. 대화 `ux-flow-v3`. Spec Writer가 이어받아 `docs/SPEC.md`에 반영한다.

## 범위 결정

- 2026-10-29 팀 기준 개정: 사용자 결정(팀 문서 우선)으로 화면 흐름이 팀 03 A-7의 4단계와 「다음」 버튼으로 바뀌었다. 아래 AC-19·20·23·24는 지우지 않고 「대체됨」으로 표시했고, 새 기준은 `docs/SPEC.md`의 「팀 기준 개정」(AC-27~45)에 있다. AC-12~18, AC-21, AC-22, AC-26은 ③·④ 단계에서 그대로 적용된다. 이 파일의 「2단계 화면」은 SPEC의 ④ 저장 단계다.

- 사람 요청 4건은 범위 변경으로 승인되었다. 수락한다. 화면 배치와 흐름만 바꾸기 때문이다.
- 바꾸지 않는 것: 계산식, 판정, Excel 셀 값, 검증 규칙, 오류 문구 규칙, 성적서·서버·저장소 기능(범위 밖).
- 흐름이 바뀌어 기존 시험이 깨지면 SPEC 기준으로 고친다. 시험을 약하게 바꾸지 않는다.
- 번호는 기존 AC-1~AC-11 다음인 AC-12부터 쓴다. `[가정]` 표시는 Spec Writer가 확정한다.

## ① 장비 정보 두 묶음

- **AC-12** Given 결과가 나온 화면일 때, When 장비 정보를 보면, Then 장비 정보가 두 묶음으로 나뉜다. 한 묶음은 모델명·기기번호·최대유속·기기 종류 4칸이고, 다른 묶음은 접수번호·의뢰기관·주소·시험일자 4칸이다. 값은 지금과 같다 (최대유속은 `N m/s`). 확인 방법: 견본으로 결과를 띄우고 e2e로 묶음 2개와 각 묶음의 라벨 4개, 순서를 검사한다.
- **AC-13** 묶음 제목과 화면 문구에 「왼쪽」·「오른쪽」을 쓰지 않는다 (AC-6·AC-10 유지). 390 px에서는 두 묶음이 세로로 쌓여도 가로 스크롤이 없다 (AC-5 유지). 확인 방법: 화면 글자에 방향 말이 없는지 e2e로 검사한다. 390 px 폭에서 `scrollWidth <= clientWidth`인지 검사한다. `[가정]` 묶음 제목이 필요한지와 그 문구(예: 「장비」·「접수」)는 Spec Writer가 정한다.
- **AC-14** AC-8 유지. 1366×768 첫 화면에 종합판정 줄, 카드 3개, 장비 정보 두 묶음, 그리고 그 바로 아래 모달 버튼 3개 한 줄이 모두 보인다. 버튼 3개는 「설치 방향 및 민감도 그래프, 시험 환경 조건」, 「CLAYDOX가 가져갈 주요 셀」, 「계산에 쓴 행」이다. 이 위치는 SPEC 54fbe8d의 「장비 정보 제목 줄 오른쪽」을 사용자 요청으로 대체한다. 확인 방법: Playwright 1366×768에서 버튼 줄이 장비 정보 두 묶음 아래에 있고 버튼 3개 모두 `bottom <= 768`인지 검사한다. 간격을 줄여도 768 안에 못 넣으면 Frontend가 실측값(버튼 줄 bottom px)을 god에게 알린다. AC-14를 고칠지(예: 버튼 줄만 첫 화면 밖 허용)는 사람이 정한다. 그 결정 전에는 AC-14를 바꾸지 않는다.

## ② 그래프·환경 조건 묶음과 모달

- **AC-15** Given 결과가 나온 화면일 때, Then 지금의 「설치방향 민감도 그래프」와 「시험 환경 조건」 두 구역은 결과 화면 본문에 따로 보이지 않는다. 대신 「설치 방향 및 민감도 그래프, 시험 환경 조건」 하나를 누를 수 있다 (버튼, 키보드로 열림). 결과 화면 본문에는 「계산에 쓴 행」 표 3개와 주요 셀 표도 보이지 않는다. 이 화면의 모달은 그래프·환경 조건(AC-16), 주요 셀(AC-17), 계산에 쓴 행(AC-26) 3개다. 확인 방법: e2e로 모달이 닫힌 상태에서 본문에 두 제목과 계산에 쓴 행 표 3개(반복성·직선성·설치방향 민감도)가 없고, 모달 버튼이 3개 있는지 검사한다.
- **AC-16** When 그 버튼을 누르면, Then 모달이 화면 앞에 뜨고 30 %·70 % 그래프 2개와 환경 조건 표(대기압·온도·습도의 최소·최대·중간값)를 함께 보여준다. 그래프와 숫자는 지금과 같다 (기준선 4 %, 최대점 빨강 표시 포함). 확인 방법: e2e로 모달 안 그래프 2개와 표 3행, 값이 지금 화면 값과 같은지 검사한다.

## ③ 주요 셀 모달

- **AC-17** Given 결과가 나온 화면일 때, When 장비 정보 두 묶음 아래 버튼 줄의 「CLAYDOX가 가져갈 주요 셀」을 누르면, Then 모달이 떠서 주요 셀 표 23행을 보여준다. 표 내용과 「숫자는 앞 10자리까지」 안내는 지금과 같다. 확인 방법: e2e로 버튼 위치(장비 정보 아래 버튼 줄 안)와 모달 안 표 23행을 검사한다. (2026-10-22 개정: 처음의 「2단계 화면에 둔다」 가정은 사용자 요청으로 결과 화면 버튼 줄로 바뀌었다.)

## 계산에 쓴 행 모달 (추가 요청, 2026-10-22)

- **AC-26** Given 결과가 나온 화면일 때, When 버튼 줄의 「계산에 쓴 행」을 누르면, Then 모달이 떠서 지금 본문 「계산에 쓴 행 보기」에 있던 표 3개를 같은 내용·순서로 보여준다. 순서는 반복성: 요약 CSV 값 → 직선성: 요약 CSV 값 → 설치방향 민감도: 그룹별 값이다. 열 이름과 행 값도 지금과 같다. 본문의 「계산에 쓴 행 보기」 접기 영역은 없어진다. 확인 방법: e2e로 견본에서 모달 안 표 3개의 제목 순서와 행 수가 지금 빌드와 같은지 검사한다. 접근성은 AC-18과 같다. (AC-25는 Spec Writer가 판정 카드 칸 색 규칙으로 예약했다.)

## ②·③·계산에 쓴 행 공통 모달 접근성

- **AC-18** 모달은 `role="dialog"`(또는 `<dialog>`)와 `aria-modal="true"`를 갖고, 제목을 `aria-labelledby`로 가리킨다. 열면 초점이 모달 안으로 들어간다. Tab·Shift+Tab은 모달 안에서만 돈다(초점 가두기). Esc나 닫기 버튼으로 닫힌다. 닫으면 초점이 그 모달을 연 버튼으로 돌아간다. 열려 있는 동안 뒤 화면은 조작되지 않는다. 확인 방법: e2e로 모달 3개 각각에서 열기 → Tab을 반복해도 초점이 모달 안에 있는지 → Esc → 초점이 연 버튼에 있는지 검사한다. axe 검사에서 위반 0건.

## ④ 2단계: 일반사항 입력 후 Excel 저장

- **AC-19** **[대체됨(팀 기준, 2026-10-29) → docs/SPEC.md AC-28]** Given 결과가 나온 화면일 때, When 「Excel 만들고 저장」을 누르면, Then 파일을 바로 내려받지 않고 2단계 화면으로 넘어간다. 2단계에는 CSV에 없는 일반사항 입력 칸(지금 `inputs.js`의 13칸)과 Excel 저장 버튼이 있다. 결과가 없거나 CSV 검증 오류가 있으면 「Excel 만들고 저장」은 지금처럼 비활성이다 (AC-3). 확인 방법: e2e로 버튼을 누른 뒤 다운로드 이벤트가 없고 입력 칸 13개가 보이는지 검사한다.
- **AC-20** **[대체됨(팀 기준, 2026-10-29) → docs/SPEC.md AC-29]** 2단계로 넘어가면 초점이 2단계 제목(또는 첫 입력 칸)으로 간다. 상태 알림 영역이 2단계로 넘어왔다는 것을 한 번 낭독한다. 확인 방법: e2e로 `document.activeElement`와 `role="status"` 문구를 검사한다. `[가정]` 낭독 문구와 초점 위치(제목 또는 첫 칸)는 Spec Writer가 정한다. 제목에 초점을 줄 경우 UIUX_REVIEW U1처럼 큰 초점 테두리가 보이지 않게 한다.
- **AC-21** 입력은 모두 선택이다. 13칸을 모두 비워도 저장할 수 있다. 저장한 파일 이름과 셀 값은 지금과 같다 (FR-M5-06, 빈 칸은 「-」 또는 양식 그대로). 확인 방법: e2e로 빈 입력으로 저장한 파일과 지금 빌드로 저장한 파일의 셀 값을 비교해 같은지 검사한다.
- **AC-22** 입력 검증과 오류 규칙은 그대로다. 잘못된 값(예: 피토계수 `abc`)이 있으면 저장 버튼이 비활성이고, 「입력 값에 고칠 곳이 있어 저장할 수 없습니다. …」 안내와 「고칠 칸으로」 링크가 나온다. 2단계에서는 입력 칸이 처음부터 펼쳐져 있다. AC-11의 접기 동작은 `[가정]` 2단계에서는 접기 영역이 없어져 해당하지 않는다. Spec Writer가 AC-11을 고칠지 없앨지 정한다. 확인 방법: 기존 AC-11·FR-M5-06 시험을 2단계 화면 기준으로 고쳐 통과하는지 검사한다.
- **AC-23** **[대체됨(팀 기준, 2026-10-29) → docs/SPEC.md AC-30]** 2단계에 결과 화면으로 돌아가는 뒤로 버튼이 있다. 누르면 결과 화면이 그대로 보인다 (6칸 배정, 결과, 칸에서 바꾼 파일). 다시 2단계로 오면 입력했던 값이 남아 있다. 확인 방법: e2e로 값 입력 → 뒤로 → 결과 확인 → 다시 2단계 → 값이 그대로인지 검사한다. `[가정]` 브라우저 뒤로 가기(history)까지 지원할지는 Spec Writer가 정한다. 기본은 화면 안 버튼만으로 한다.
- **AC-24** **[대체됨(팀 기준, 2026-10-29) → docs/SPEC.md AC-27, AC-28]** AC-6 수정. 「자동으로 … 이동합니다」 같은 자동 이동 문장은 여전히 없다. 결과 화면에서 2단계로 가는 길은 「Excel 만들고 저장」 하나, 돌아오는 길은 뒤로 버튼 하나다. 단계 탭은 두지 않는다 `[가정]`. 확인 방법: 화면 글자 검사, 이동 버튼 2개(앞·뒤)만 있는지 e2e로 검사한다.
